## Key Schema Changes

### New Tables (2)
1. **cv_skills** (normalized from JSONB)
   - Replaces `cv_analyses.skills` JSONB
   - Queryable proficiency levels
   - Supports skill analytics

2. **interview_questions** (junction table)
   - Replaces `interviews.question_ids[]` array
   - Tracks sequence, timing, skip status
   - Extensible for future features

### New ENUMs (3)
1. **question_type_enum**: Added `problem_solving`, `system_design`
2. **difficulty_enum**: Added `expert`
3. **proficiency_level_enum**: For cv_skills

### Removed Fields
- `cv_analyses`: cv_file_path, skills, metadata
- `questions`: tags, evaluation_criteria
- `interviews`: question_ids[], answer_ids[]
- `answers`: candidate_id, metadata, evaluation, gaps, similarity_score, evaluated_at

### Decomposed Structure
- `prompt_templates.template_json` → 11 editable columns
- Computed `template_json` column (auto-generated by DB)

## Common Pitfalls

### 1. Active Interviews During Migration
**Problem**: Migration will fail if active interviews exist
**Solution**:
```sql
-- Check BEFORE migration
SELECT COUNT(*) FROM interviews
WHERE status IN ('QUESTIONING', 'EVALUATING', 'FOLLOW_UP');
-- MUST return 0
```

### 2. ENUM Type Mismatches
**Problem**: Old string values don't match ENUM
**Solution**: Migration handles with fallbacks (technical, medium)

### 3. Missing JOINs
**Problem**: Queries fail without proper JOINs
**Solution**: Use helper views or explicit JOINs
```sql
-- Use view
SELECT * FROM cv_analysis_with_skills WHERE id = ?;

-- Or explicit JOIN
SELECT cv.*, s.* FROM cv_analyses cv
LEFT JOIN cv_skills s ON s.cv_analysis_id = cv.id
WHERE cv.id = ?;
```

### 4. Forgetting Sequence Order
**Problem**: Questions not in correct order
**Solution**: Always use `sequence_order` when adding to interview
```python
for i, question_id in enumerate(question_ids):
    await repo.add_question_to_interview(
        interview_id, question_id, sequence_order=i
    )
```

### 5. Breaking Clean Architecture
**Problem**: Domain importing from adapters
**Solution**:
- Interview model should NOT query database directly
- Use repository methods injected via use cases
- Keep domain pure (no SQLAlchemy, no DB logic)

## Rollback Decision Tree

```
Migration failed during execution?
├─ YES → Automatic rollback (transaction-wrapped)
└─ NO → Continue

Migration succeeded but data integrity issues?
├─ YES → Manual rollback: alembic downgrade -1
└─ NO → Continue

Application deployed but critical errors?
├─ YES → Restore backup + deploy old code
└─ NO → Monitor for 24 hours

Performance degradation >10%?
├─ YES → Investigate, optimize queries, or rollback
└─ NO → Success!
```
