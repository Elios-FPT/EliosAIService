### Integration Tests (Real DB)

**Test File:** `tests/integration/test_prompt_api_integration.py`

**Setup:**
- Use test database (via ENVIRONMENT=test)
- Run migrations: `alembic upgrade head`
- Seed test data (prompts v1, v2, executions)

**Test Scenarios:**

1. **Version Lifecycle:**
   - Create initial prompt → assert v1, is_draft=True
   - Create new version → assert v2, parent_version_id set
   - Rollback to v1 → assert v3 created with v1 content

2. **Activation Workflow:**
   - Activate v1 (traffic=100%) → assert v1 active, others inactive
   - Activate v2 (traffic=50%), v3 (traffic=50%) → assert both active (A/B test)
   - Adjust v2 traffic to 75% → assert updated, v3 still 50%

3. **Analytics & Audit:**
   - Execute prompt → log execution
   - Query analytics → assert metrics correct
   - Query audit trail → assert activation logged

4. **Pagination:**
   - Create 50 prompts
   - List page 1 (size=20) → assert 20 items, has_next=True
   - List page 3 → assert 10 items, has_next=False

5. **Error Cases:**
   - Get non-existent prompt → 404
   - Create duplicate prompt → 400
   - Activate deleted prompt → 400
   - Rollback to non-existent version → 400

**Teardown:**
- Delete test data
- Drop test database

### E2E Tests (Full Stack)

**Test File:** `tests/e2e/test_prompt_management_e2e.py`

**Scenario:**
1. DevOps creates initial prompt v1 via API
2. ML engineer creates v2 with improved system_prompt
3. DevOps activates v2 with traffic=20% (A/B test)
4. System executes prompt 100 times (weighted selection)
5. ML engineer queries analytics (success rate, cost)
6. DevOps increases v2 traffic to 100% (full rollout)
7. Verify audit trail shows all changes

```markdown
## Prompt Management API

Manage LLM prompt templates with version control and A/B testing.

### Endpoints

**Version Management:**
- POST `/api/prompts` - Create initial prompt
- POST `/api/prompts/{name}/versions` - Create new version
- POST `/api/prompts/{name}/rollback` - Rollback to previous version
- GET `/api/prompts/{name}/versions` - Get version history
- GET `/api/prompts/{name}/versions/{version}` - Get specific version
- GET `/api/prompts/{id}` - Get prompt by ID

**Activation & A/B Testing:**
- PATCH `/api/prompts/{id}/activate` - Activate version
- PATCH `/api/prompts/{id}/traffic` - Adjust A/B test traffic
- GET `/api/prompts/{name}/active` - Get active prompt

**Analytics & Audit:**
- GET `/api/prompts/{name}/analytics` - View analytics summary
- GET `/api/prompts/{name}/audit-trail` - View change history
- GET `/api/prompts` - List all prompts (paginated)

### Usage Example

\`\`\`python
import httpx

# Create initial prompt
response = await client.post("/api/prompts", json={
    "prompt_name": "answer_evaluation",
    "system_prompt": "You are an expert interviewer...",
    # ...
})
prompt = response.json()

# Activate for production
await client.patch(f"/api/prompts/{prompt['id']}/activate", json={
    "changed_by": "admin",
    "reason": "Deploy v1 to production",
    "traffic_percentage": 100
})
\`\`\`

### A/B Testing Workflow

1. Create v2 with improved prompt
2. Activate v2 with traffic=20% (gradual rollout)
3. Monitor analytics for success rate, cost
4. Increase traffic to 50%, 75%, 100% based on results
5. Rollback if v2 underperforms
```
